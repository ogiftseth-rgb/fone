# FoneFlex v0.8 — Progressive Web App (PWA)

This is a WAMP-compatible PWA enhancement for the existing FoneFlex v0.7 application. It adds an install experience for Android/Chromium and iOS/iPadOS, a standalone app manifest, service-worker lifecycle/update handling, a safe offline screen, mobile safe-area styling, and connectivity messaging.

## Important scope and security behaviour

- This is the same FoneFlex PHP application presented as an installable web app; it is not a separate native Android/iOS codebase.
- Customer records, KYC images, M-Pesa statements, agreements, payment pages and API responses are **not cached** by the service worker.
- Creating customers, recording payments, signing agreements, changing device states and remote OEM commands require a live server connection. FoneFlex does not queue financial or identity transactions for offline submission.
- The PWA install shell does not itself implement web push notifications. Push requires server-side Web Push/VAPID support, a subscription table, notification preferences, and event-triggered delivery.
- Camera and geolocation require a secure context. Use HTTPS for the deployed/staging site. `localhost` is allowed for local desktop development but does not make a WAMP site on a PC accessible as a secure origin from a phone.

## Prerequisites

- Existing FoneFlex v0.7 WAMP installation.
- PHP 8.3+ and the existing MySQL database/migrations.
- A valid HTTPS URL for real Android/iPhone installation and camera testing.
- Apache must serve the `public` directory as the web root, as in the existing FoneFlex vhost setup.

## Install the overlay

1. Back up `C:\wamp64\www\FoneFlex` and export the `foneflex` database.
2. Extract `FoneFlex_v0.8_WAMP_Overlay.zip` into `C:\wamp64\www`, merging into the existing `FoneFlex` folder.
3. Preserve `config\config.php`, the configured data-encryption key, and all existing customer files.
4. No SQL migration is required for this PWA shell update.
5. Restart Apache/WampServer and open FoneFlex over HTTPS (or `http://localhost` for desktop-only local development).

## Run checks

```powershell
& 'C:\wamp64\bin\php\php8.3.14\php.exe' 'C:\wamp64\www\FoneFlex\bin\check_v08.php'
```

Then in Chrome DevTools → Application:
- Manifest: confirm FoneFlex name, icons, start URL and standalone display.
- Service Workers: confirm `/sw.js` is activated and controlling the page after refresh.
- Clear old site data once after deploying this service-worker version if the old app shell remains cached.

## Install on Android

1. Open the HTTPS FoneFlex address in Chrome or Samsung Internet.
2. Sign in, then tap **Install FoneFlex** when the install button appears. Alternatively use the browser menu → Install app / Add to Home screen.
3. Confirm installation. Launch FoneFlex from the phone's app launcher.

## Install on iPhone/iPad

1. Open the HTTPS FoneFlex address in Safari (recommended).
2. Tap Share.
3. Choose **Add to Home Screen**.
4. Keep **Open as Web App** enabled if shown, then tap Add.
5. Launch FoneFlex from the Home Screen and sign in.

The in-app Install FoneFlex button displays these steps on iOS because iOS does not expose Chromium's `beforeinstallprompt` install event. iOS/iPadOS 16.4+ supports Web Push for Home Screen web apps, but push delivery is not included in this v0.8 package.

## Offline behaviour

The service worker caches only the static shell (CSS, JavaScript, icons, manifest and offline page). Authenticated HTML routes with query strings remain network-only. If the server cannot be reached, the user sees a generic offline page. No customer, payment, KYC or agreement data is stored in the service-worker cache.

## Production deployment checklist

- Configure a real domain and valid TLS certificate; use HTTPS throughout.
- Set secure session cookies and enable HTTPS-only configuration after validating the HTTPS deployment.
- Confirm Apache serves `public/manifest.webmanifest` with a JSON-compatible MIME type and `public/sw.js` as JavaScript.
- Confirm service worker scope covers the deployed application directory.
- Test on a current Android phone and an iPhone/iPad, including camera permissions, sign-in, session expiry and logout.
- Run a security review before enabling push or offline data features.
