# FoneFlex v0.7 — WAMP installation guide

## What changed

New hire-purchase agreements now calculate interest using the reducing-balance method. The agreement form asks for a nominal annual interest rate (% p.a.). FoneFlex calculates periodic interest on the opening outstanding principal for every instalment, builds the amortisation schedule, and displays the total agreed interest and estimated instalment before submission.

Conventions used to convert the nominal annual rate to a periodic rate:

- Daily: annual rate / 365
- Weekly: annual rate / 52
- Fortnightly: annual rate / 26
- Monthly: annual rate / 12

Formula for each period:

`Period interest = opening principal balance × periodic rate`

The scheduled payment is calculated using the standard amortising-payment formula. Each payment reduces principal; therefore the interest amount declines as the outstanding principal reduces. Total agreed interest is the sum of all scheduled period interest.

Existing agreements are retained as `legacy_flat`. Their interest amounts and schedules are not recalculated. The FoneFlex revenue share continues to be calculated from verified interest actually collected and allocated.

An agreed deposit is deducted from financed principal at the start. If a bank or M-Pesa deposit is pending verification, the agreement remains `under_review` until that initial deposit is verified. The verified initial deposit is recorded as the upfront principal contribution rather than being applied a second time to the first scheduled instalment.

## Package contents

- `FoneFlex_v0.7_WAMP_Overlay.zip`: merge overlay for an existing FoneFlex WAMP installation.
- `FoneFlex_Development_Package_v0.7_WAMP.zip`: complete application source package.

## Upgrade from the v0.5 WAMP installation

1. Back up `C:\wamp64\www\FoneFlex` and export the `foneflex` database in phpMyAdmin.
2. Extract the v0.7 overlay into `C:\wamp64\www`, allowing the `FoneFlex` folder to merge. Preserve your existing `config\config.php` and customer encryption key.
3. In phpMyAdmin, select the `foneflex` database.
4. Run migration `006_oem_live_integrations.sql` first, if it has not already been applied.
5. Run `007_reducing_balance_interest.sql` once. Do not rerun it after the two new columns have been created.
6. Run the verification command below.

From PowerShell:

```powershell
& 'C:\wamp64\bin\php\php8.3.14\php.exe' 'C:\wamp64\www\FoneFlex\bin\check_v07.php'
```

## Verify calculation independently

```powershell
& 'C:\wamp64\bin\php\php8.3.14\php.exe' 'C:\wamp64\www\FoneFlex\tests\reducing_balance_test.php'
```

Expected output begins with:

`PASS: reducing-balance amortisation tests.`

## Example

For KES 100,000 financed over 12 monthly instalments at a nominal annual reducing-balance rate of 24%:

- Monthly periodic rate: 24% / 12 = 2%.
- Period 1 interest: KES 2,000.00.
- Subsequent interest is calculated on the lower opening principal balance.
- Total scheduled interest from the tested amortisation schedule: KES 13,471.53.

The figure is an illustration of the calculation method, not a recommended lending rate. Retailers must set lawful and properly disclosed rates and fees.

## Important notes

- This uses nominal APR divided by standard periods-per-year conventions; it is not an effective annual rate conversion.
- New agreements use reducing balance. Legacy agreements are unchanged.
- If the customer signs an agreement, the displayed rate, repayment schedule, total interest, deposit treatment and all fees should be included in the signed contract before the phone is released.
- Database-backed verification must be performed against your WAMP database. The build environment cannot access that database.
